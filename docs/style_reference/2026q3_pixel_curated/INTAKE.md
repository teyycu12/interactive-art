# 2026q3_pixel_curated — 像素風格的參考圖集與素體

> **2026-10-15 起是這一組**：4 張三視圖＋1 張素體。前一組（6 張單一正面、90 格、
> 3 頭身）畫風不同，已整組移除，只留在 git 歷史裡。

## 這組圖是什麼

生成一個角色時，模型一次收到四張圖：

| | 內容 | 權威範圍 |
|---|---|---|
| Image 1 | 參與者的照片 | **誰**：臉、膚色、髮色、身上實際穿什麼、什麼顏色（**不含**體型與身高） |
| Image 2 | 同一張照片的局部近拍 | 同上，只是細節 |
| Image 3 | **素體** `pose_turnaround.png` | **身材**：身高、頭身比、手腳長度、每一面的站姿、三視圖的排法 |
| Image 4 | **參考圖集** `turnaround_*.png` 拼成的 sheet（2×2） | **怎麼畫**：格子多粗、幾階顏色、輪廓怎麼下、衣服與配件怎麼繞到側面背面 |

| 檔案 | 是什麼 |
|---|---|
| `turnaround_01`–`04.png` | 每張一個角色：正面｜右側（朝右）｜背面，1536×864，與生成的輸出同一個排法 |
| `pose_turnaround.png` | 素體：同一個畫風、同一個身材、穿最素的衣服（淺灰 T 恤、灰長褲、貼頭短髮）的人。模型把參與者的衣服穿到它身上 |
| `_original/` | 原圖、素體原檔與 `layout.json`（每張原圖由左到右是哪一面） |

**為什麼是三視圖＋素體**：生成要畫三視圖，參考圖若只有正面，側面背面模型只能自己想，
比例就在那裡跑掉；姿勢圖若是灰色方塊（沒有臉、沒有畫風），對模型只是抽象提示，照片裡
真人的比例常常贏過它 —— 同一批角色有 3 頭身也有快 5 頭身。現場 30 人同時生成，不能靠
「不合格就重生」，個頭要一次就對，所以從輸入下手。

兩件必須先知道的事：

1. **每生成一次，這幾張圖就會被傳給第三方服務一次**（OpenRouter → Google）。
   所以來源與授權要寫進 `../PROVENANCE.md`，不能事後補。
2. **這不是訓練資料**，沒有任何權重被更新；它是 prompt-time 的條件輸入。

## 量出來的比例（prompt 照這組寫）

四張一致：角色約 **75 格**高（一格約 8.6px，總高 636–665px，差在頭髮）、約 **2.2 頭身**
—— 頭含髮到下巴 45%、領口 49%、腰 72%、鞋頂 92%。正面寬高比最寬 0.60（蓬鬆捲髮），
`max_aspect` 因此是 0.75。

這組數字同時寫在 `garment_gen` 的 prompt（`PIXEL_ART_GRID_HEIGHT` 與第 2、3 條）、
`turnaround.CELLS_PER_FIGURE`，而素體是照這組圖畫的。三邊對不上時模型會誰都不聽，
直接畫成寫實比例（2026-09-24 實測過一次）。

## 一定要做到的（換圖時照這張清單）

**每張都一樣**（只要一張不同，模型就收到兩種標準）：

- 構圖：一張一個角色、三個人一排、同高同地平線、人與人之間至少約 8 格純白；
  背景純白，無陰影、文字、格線、外框。排法與側面朝向不必照順序，`layout.json` 會整理
- 比例：頭身比與比例尺完全相同。**不縮放**：同一個比例尺下身體一樣大，總高只差在
  頭髮；各自縮放成同高反而讓個頭不一
- 畫法：格子大小一致、硬邊、每材質 3–5 階、各材質自己的最暗階當輪廓（最暗維持在
  `#302A2D` 附近的暖深灰，與大螢幕像素場景的墨色同一家族）、光從左上前方
- 姿勢：正面背面手臂外張、手與身體間有空隙（走路分析要靠它分出手）；側面手垂在身體
  前面、手掌畫出來；背面沒有臉；雙腳有鞋

**每張都錯開**（重複出現的東西會滲進每個角色，`_STYLE_SHEET_FIREWALL` 的禁令擋不住）：

- 髮色、髮型、膚色、衣服件別與顏色、體型的胖瘦
- 裙子或洋裝至少一張（一整塊、不縱切，裙襬下才是腿）
- 背包、眼鏡各只出現在一張，而且那張的三面都要畫到；不放帽子

## 流程

```bash
# 1. 原圖放進 _original/，在 layout.json 寫上每張由左到右是哪一面（side-left 會被鏡像成朝右）
python scripts/prepare_turnaround_reference.py docs/style_reference/2026q3_pixel_curated/_original \
    --out docs/style_reference/2026q3_pixel_curated
# 2. 閘門檢查（剛好三個人、腳底同線、夠高、邊上沒有雜點）
python scripts/check_reference_set.py docs/style_reference/2026q3_pixel_curated
# 3. 在 ../PROVENANCE.md 補上每個檔案的來源與授權
# 4. 頭身比或格數變了：改上一節列的那幾處數字，然後跑 pytest backend/
# 5. 重啟生成服務（sheet 與素體在記憶體裡快取）
```

整理腳本只做排版與清背景，**不重新定格、不量化**：生圖模型交出來的是「像素風插畫」，
格距浮動（這組一格約 8.6px 上下），硬切成整數格會讓每格混到隔壁格（實測邊緣密度
0.056 → 0.045，肉眼是糊掉、變髒，檔案卻仍然很「像素」）；中位切割量化會併掉虹膜那種
小面積的關鍵色（實測 64 色時綠眼睛變藍眼睛）。這種來源的圖只能洗，不能重畫。

**素體怎麼來的**：用生圖模型照四張參考圖畫一個中間膚色、貼頭短髮、淺灰 T 恤灰長褲的人
（`_original/base_body.png`），`layout.json` 的 `height` 把它縮放到短髮那張（02）的正面高，
與參考圖同一個比例尺。**換參考圖時素體要跟著重做** —— 兩邊比例對不上，模型同時收到兩種身材。

## 仍然成立的經驗

- **格數不能為了投影機調粗**：曾經設 64 格（投影機上一格 2~3 個裝置像素，最像像素畫），
  做出來臉變馬賽克被否決 —— 這件作品的核心是參與者認得出那是自己。格數取參考圖自己的格距。
- **還沒解決的一項**：貼圖從生成到投影經過兩次**平滑**重新取樣（`slicer.normalize()` 的
  LANCZOS、大螢幕的 `imageSmoothingQuality='high'`），格子細時顆粒感會變弱。投影出來若
  「像低解析度的柔邊角色，不像像素畫」，正解是讓渲染端知道角色是像素風格並關掉平滑：
  `/generate` 回的 `styleId` 目前沒有被帶進 `pendingScanConfig`，那是一整條獨立的接線
  （styleId → avatar → 伺服器 → 大螢幕），不要混進換圖這一步。
- **上線前最後一關是肉眼**：把生成的角色放到大螢幕的像素場景前面看
  （`public/screen/index.html?scene=kitchen`）。墨色、格子粗細、飽和度若對不上，
  問題幾乎都在參考圖，不在 prompt。
