## 這組是什麼

5 張全身參考圖，作為 `full_character` 生成時的 **Image 4（風格 sheet）**。

**這不是訓練資料。** 沒有任何權重被更新。這些圖是 **prompt-time 條件輸入**：
`backend/garment_gen.py` 的 `_build_style_reference_sheet()` 每次生成時把它們拼成一張
1024×1536 的 sheet，連同訪客照片一起送往 OpenRouter → Google。也就是說，
**每一次生成都會把這 5 張圖傳輸給第三方服務**。

檔案是執行期資產：沒有它們，`_style_reference_sheet()` 會印出
`not found, sending without it` 並退回三張圖的送法，生成不會失敗，但物種統一效果會消失。

## 殘留風險

**浮水印仍是未解的一項。** 原始檔帶浮水印、出貨檔已移除，這與 5.2(i) 讀法無關 ——
浮水印是權利主張最明確的形式，移除它在部分司法管轄區屬於獨立的問題，
不因「非商業」而免除。

採取的緩解措施：**帶浮水印的原始檔一併納入版本控制**（`_original_watermarked/`）。
公開的是「原始素材 + 明確標示為衍生的工作檔」，而不是只有去浮水印的版本 ——
來源可被任何人驗證，不構成冒充自有素材。這降低曝險但不消滅它。

**這份文件不會讓散布變得合法。** 它記錄的是「依據什麼判定、由誰判定、還剩什麼風險」。
判定若被推翻，正確的動作是把檔案移出版控並更新這裡，不是修飾文字。

**目前結論**：發布到 GitHub —— 依上表已執行（學術、非商業）。
展覽現場展示 —— 風險低於散布，未見明文禁止。兩者共通的殘留風險是浮水印那一項；
若要徹底解除，見〈若查不出來源〉的重生方案。

## 已知品質限制

兩項在 `docs/STYLE_PROBE_FOLLOWUPS.md` 已記錄的實測問題，若日後重生這組請一併修正：

1. **5 張裡有 4 張雙腿併攏成實心柱**，只在鞋子附近（約 96% 高度）才分開。
   這與 prompt 自己的 `MANDATORY LEGO DESIGN RULES #1`（雙腿間需有可見垂直間隙）
   及 `_canonical_lego_pose()` 畫的 24px 間隙直接衝突，也使分部位身高縮放
   在幾何上量不到 inseam。`full_body_03`（一體式洋裝）正當豁免。
2. **5 張髮色全落在 hue 16°–32°、saturation ≥ 92** 的窄帶。`_STYLE_SHEET_FIREWALL`
   雖明文禁止髮色轉移，但單一色帶重複 5 次是否造成偏壓，需要用
   `STYLE_REFERENCE_MODE=off` 做 A/B 實測，不能用推論的。
